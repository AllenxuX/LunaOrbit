# Kafka 账号密码入口与平台用词优化

用户要求：当前三个账号没有查看密码选项；平台应使用普通 Kafka 管理平台的语言，不使用“托管”等实现术语。沿用 frontend-design、vue-best-practices 与现有后台视觉规范。

实际排查：用户当前登记位于实验目标 Kafka。Kafka 只读查询确认 3 个 SCRAM-SHA-256 账号；该登记没有工作台密码保存记录。不得把其他用户登记下的密码复制过来，不自动重置 Kafka 密码。

交互：账号独立密码列，始终显示查看密码入口；未保存、无查看权限分别给出直接原因。已有账号可从行内录入现有密码（验证后保存，关联应用可选）；已有密码通过弹窗查看/复制，30 秒或关闭/离页/切集群/失去权限后清除。应用列表提供查看账号入口，通过服务端 application_id 过滤账号并正确分页。不改变账号创建、ACL 或审批权限。

用词：托管→保存密码，账号开通→创建账号，凭据→账号密码/认证信息（按上下文），回读核验→检查结果，观测→查询/状态，证据→详情/检查信息，登记→添加/集群配置，受控变更→变更管理。保留必要 Kafka 参数名、ACL 等行业术语。只修改产品文案，不改 API 路径、机器状态码或审计字段。

验证：密码缺失和无权限入口、显式查看与复制/清理、录入不改 Kafka 密码、按应用过滤在分页前完成；Go test/vet，前端 test/typecheck/lint/build，实验浏览器只读检查三个账号状态；需要测试密码的流程只使用合成 Mock 数据，输出和截图不包含真实密码。更新路线图和日志，完成后停止。

实施与验收已完成：账号密码列、录入与查看弹窗、应用账号过滤、平台界面用词。Go 全量测试/vet/Linux 构建，前端138项测试/类型检查/lint/构建，实验桌面及手机账号入口、单向拓扑和中文配置说明浏览器回归通过。详细命令、实际边界与部署结果见开发日志。
