# Topic 详情与平台文案优化

用户要求：Topic 列表点击名称进入独立详情页，集中查看分区、配置并修改；全站减少不必要说明，遵循后台设计规范。权限认证产品方案继续暂缓。

设计：沿用浅灰底 #f4f6fa、白色内容 #ffffff、深色文本 #243650、次要文本 #64748b、蓝色操作 #2563eb、危险操作 #dc2626；字体沿用系统中文无衬线，标题 22/18px，正文 14px，表格与辅助信息 12–13px。左对齐，单一内容主列；不叠加介绍卡片。

结构：集群 / Topics / Topic 名称 → 概要（分区、副本、ISR）→ 分区、配置、副本调整、操作记录。删除置于更多操作。列表只负责筛选分页与导航；详情视图拥有 Topic 及异步路由状态；配置组件拥有查询筛选及编辑抽屉；操作组件负责资源范围记录与执行核验。修改后进入该 Topic 操作记录，保留现有审批/异步回读行为。

配置：常用参数有中文名称及单位；保留 Kafka 原始参数名便于专业用户核对。文档、默认值和同义来源收起，中文显示来源；未知不伪造。修改使用 Element Plus 抽屉，预览置于同一抽屉，不继续向列表尾部堆表单。

文案：主界面优先名称、状态与动作；环境标识集中在顶栏；技术证据移入诊断。保留错误、未知、只读及破坏性操作确认。应用/权限只精简展示文案，不修改认证授权语义。

验证：Topic 深链接/返回、浏览器前进后退、切 Topic 清理旧数据、内置 Topic 保护、修改后的资源范围记录；Go test/vet，前端 test/typecheck/lint/build，真实实验浏览器桌面及移动布局，更新路线图和日志并部署本轮界面。

完成：Topic 独立详情、常用/完整配置与编辑抽屉、全站文案收敛已实施并部署。131 项前端测试、Go 全量 test/vet、前端类型/lint/build、真实两版本桌面及移动流程、拓扑回归通过。截图检查发现并修复移动端全局表格最小宽度冲突。详见 IMPLEMENTATION_LOG 对应条目。
