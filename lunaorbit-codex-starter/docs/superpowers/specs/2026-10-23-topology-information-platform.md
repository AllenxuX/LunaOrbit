# LunaOrbit：内网消息拓扑与信息记录平台

日期：2026-10-23。依据用户最新要求：不再建设权限管理；不需要登录，仅供内网使用。本文为收敛方案，尚未修改运行系统。与历史LDAP、RBAC、账号和ACL产品要求冲突时，实施以本次确认的定位为准。

## 推荐范围

导航保留运维总览、Kafka集群、同步拓扑，新增Topic链路、应用信息。集群详情保留Broker、Topic、分区、消费组、同步关系等查询；配置值作为信息可查。应用只记录名称、负责人、说明、环境、生产/消费Topic及消费组关系，不绑定账号开通、密码交付或ACL生成。

移除登录/会话管理、平台访问控制、角色/团队授权、身份与权限、Kafka账号/密码和ACL管理、变更审批入口。按“拓扑+记录”定位，推荐同时下线Kafka/MM2实际配置修改、Topic创建删除、消费位点重置等运维写接口。信息登记仍可增改，例如集群接入、负责人、应用关系、备注和标签；不会因此修改Kafka或MM2运行配置。

比较：仅隐藏菜单成本低，但后台敏感接口仍存在且产品定位未收敛，不采用。推荐以无登录的共享工作空间运行，后台不注册权限/密码交付/基础设施写路由；复用现有只读采集和拓扑模块。另起新项目会丢失已验证能力，没有必要。

## 现有代码检查结果与迁移

frontend/src/App.vue包含权限、访问控制、变更、会话入口；router.ts包含对应页面与应用/账号详情路由。KafkaWorkspace.vue同时依赖ensureSession、权限meta、应用授权、团队和写操作组件，不能只删侧边栏。

后台集群注册、发现和视图存在owner维度；取消登录不是伪造一个全权限管理员。需要新增明确的共享工作空间上下文，资源按workspace归属，旧用户数据迁移先预览、处理重复登记和冲突，再执行事务迁移。不能无条件合并所有owner资源、泄露历史密码或跨集群复制凭据。

共享范围包括集群登记、发现映射、应用关系和备注；记录保留revision与更新时间，冲突返回409，不静默覆盖。未登录时不能声称知道真实操作者。浏览器偏好（布局、缩放、筛选）留在本浏览器，不作为共享图坐标；原个人布局不删除、不自动覆盖所有访问者。

集群SASL/TLS和Kite凭据仍是采集连接配置，仅后台使用，普通查询不回传秘密。历史ACL/账号数据不做Kafka侧删除；历史敏感记录不经匿名接口开放。保留已有出站地址限制、超时、采集限流、请求脱敏与信息记录并发控制。

## Topic链路第一版

从Topic详情的“查看链路”和全局“集群+Topic”搜索进入。资源唯一身份为cluster registration ID + 完整Topic名称，不按裸Topic名合并跨集群节点。默认展示一跳，按需展开上下游，保留当前查询根节点；支持完整路径聚焦和有限深度追踪，检测环路并提示截断。

节点：应用、具体集群的Topic、MM2同步任务、消费组。边：登记的生产关系、登记的消费关系、实际观测的消费关系、配置匹配的同步关系。所有边都有来源、时间、状态；历史位点与当前成员分配分开显示。空闲组不等于从未消费，提交过位点不等于当前订阅。

同步解析以现有Kite发现和MM2契约为基础：核对源Topic是否被规则匹配、排除规则、策略及目标实际Topic。DefaultReplicationPolicy、IdentityReplicationPolicy应分别解析；自定义策略无法解析时明确显示目标待确认，不凭Topic同名推断。多跳逐段匹配实际Topic名，避免将A.orders直接等同于orders。配置或目标存在均不证明业务消息全程到达。

生产者采用应用信息登记关系，明确标记“人工登记”；已有Kafka常规管理数据不能完整列出生产者，不从ACL推断实际使用。不在第一版部署业务探针或假造自动发现生产者。未关联应用的消费组直接显示组名。订阅/成员/分配数据按已有客户端能力补采集，采集失败或不支持显示未知，并保留最后成功观测时间。

应用表单：名称、负责人、环境、说明、生产Topic、消费Topic、消费组；Topic选择必须带集群，关系可编辑且保留来源。页面文案使用应用、生产、消费、同步、负责人、备注等常规词汇，不出现授权或账号交付流程。

## 实施顺序与验收

第一批：无登录共享工作空间、旧数据迁移预览和冲突处理、导航/路由/API收敛、应用信息登记；验证匿名可查、可登记，历史密码/ACL/运维写接口不可访问，记录共享、浏览器布局隔离、已有四Kafka拓扑与集群详情不回退。完成一批后报告。

第二批：Topic链路后端模型与有界查询、MM2逐段命名/匹配、消费关系证据、应用登记关系及X6页面。用Mock覆盖同名跨集群、两种命名策略、自定义策略未知、环路、多源多目标、历史位点、采集失败和规则排除；再在专用四Kafka两MM2实验中验证真实Topic与消费组。无生产写操作。

尚未验证：现有实验消费组能否提供完整成员订阅与分配、具体Topic在两段MM2上是否连续匹配、生产应用的真实清单。正式实现需进一步读采集器和接口测试，不能将本设计当作已实现或已验证。
